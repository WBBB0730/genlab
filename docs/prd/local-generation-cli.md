# local-generation-cli

**本地生成命令行工具**

## Problem Statement

用户在各个**代码项目**（游戏、小程序、网页等）里和本地 agent（Claude Code、Codex 等）一起干活，经常需要图片、视频、配乐、音效和语音。现有的 GenHub 是团队网页工具：要飞书登录、进项目、过权限，背后是 Supabase、webhook 和 Vercel，agent 没法直接调用，生成结果也不在本机，而且只支持图片和音乐。

- kie.ai 的生成结果 14 天后失效，只拿到链接等于没拿到。
- 现成的开源工具 kie-cli-mcp 只返回 kie 的链接，不把成品下载到本地，而且默认每次生成都要人工确认。
- 提示词、参数、参考输入和「这一版是从哪一版改来的」需要和成品一起留下来，事后能追查、能接着改、能原样重做。

## Solution

做一个命令行工具 `genlab`，配一份给 agent 看的使用说明（skill）。agent 在代码项目里调用一条命令，工具就向 kie.ai 下单、自己轮询结果、把产物下载进本机的**库**，返回文件的完整路径，并留下完整的生成记录。支持图片、视频、音频三种素材类型，音频涵盖音乐、音效与语音。

- **库**集中放在配置指定的目录里，不随代码项目的清理而丢失（见 ADR-0003）。
- 以 npm 包 `genlab` 发布，`npm install -g genlab` 或 `npx genlab <命令>` 即可使用。
- 库的组织沿用 GenHub 内容重组之前、以**素材**为核心的模型：**项目** → 可嵌套的**文件夹** → **素材** → **版本**（见 ADR-0001）。
- 库就是普通的文件夹：每个素材一个文件夹，里面是记录文件、各版本产物和**参考输入**副本，在 Finder 里看到的就是库本身（见 ADR-0002）。
- **代码项目**通过**项目映射**自动对应到库里的**项目**，worktree、目录改名、重新 clone 都不影响（见 ADR-0004）。
- 可用模型与参数实时取自 kie 的模型目录与 schema，不写死（见 ADR-0005），覆盖 kie 上全部图片、视频、音频模型。下单、查结果、结果解析复用 GenHub 已验证的代码。
- `genlab init` 一条命令写好配置。

## User Stories

1. As an agent, I want 用一条命令新建素材并生成图片、视频或音频, so that 在代码项目里就能直接拿到需要的资源
2. As an agent, I want 命令等到生成完成后返回每个版本的状态和产物的完整路径, so that 拿到结果马上就能用
3. As an agent, I want 等待超过上限时先拿到当前状态、之后用等待命令接着等, so that 不会被自己的命令超时打断
4. As an agent, I want 一次提交多个生成后统一等待, so that 并行产出多个资源
5. As an agent, I want 一次生成多份并列的结果, so that 给用户几个方案挑选
6. As an agent, I want 在参数里直接引用本机文件（参考图、首帧、参考音视频）由工具上传, so that 基于已有素材生成
7. As an agent, I want 使用 kie 上任意图片、视频、音频模型及其全部参数, so that 不受工具内置清单限制
8. As an agent, I want 生成前查到模型的价格与参数表, so that 填对参数、控制花费
9. As an agent, I want 对某个就绪版本做 AI 编辑（图片、音乐、视频）, so that 在它的基础上按要求修改
10. As an agent, I want 沿用某个版本当初的生成输入在同一素材里重新生成、只改其中几项, so that 不用手抄全部参数
11. As an agent, I want 原地重试失败的版本, so that 不必重新发起、版本号也不变
12. As an agent, I want 把外部图片、视频或音频导入为新素材的第一个版本, so that 能对代码项目里已有的文件做 AI 编辑
13. As an agent, I want 把某个就绪版本设为当前版本, so that 标记用户选中的那一版
14. As an agent, I want 查看素材的全部版本、状态、生成输入与文件路径, so that 知道每个版本怎么来的、在哪里
15. As an agent, I want 列出当前项目的素材并能按类型筛选, so that 先看看已有什么、沿用已有的文件夹分法
16. As an agent, I want 按类型和关键词筛选模型目录, so that 快速找到合适的模型
17. As an agent, I want 在任何代码项目及其 worktree 里调用时自动落到对应的项目, so that 不用每次说明项目名
18. As a 用户, I want 没有远程仓库的代码项目第一次使用时登记一次项目名、之后一直沿用, so that 项目名稳定不变
19. As a 用户, I want 代码项目中途建了远程仓库后仍对应原来的项目, so that 成品不会被拆到两处
20. As a 用户, I want 改项目映射就能改项目名、或把多个代码项目归到同一个项目, so that 按自己的意思组织
21. As a 用户, I want 所有成品和记录集中存在配置指定的目录, so that 不会因为代码项目的清理、重新 clone 或 worktree 清理而丢失
22. As a 用户, I want 在 Finder 里按 项目 / 文件夹 / 素材 浏览，并直接改名、移动、删除素材或文件夹, so that 不用为整理库另学命令
23. As a 用户, I want 每个版本完整保存模型、输入参数、参考输入、来源以及与 kie 往来的原始数据, so that 任何时候都能追溯和复现
24. As a 用户, I want 工具中断后再运行任意命令时自动补收没完成的生成, so that 14 天内不会丢成品
25. As a 用户, I want 删除没有子版本的版本, so that 清理不要的结果又不打断来源链
26. As a 用户, I want 自己在终端里也能用同样的命令, so that 不经过 agent 也能出图
27. As a 用户, I want 一条命令交互式填写 API Key 与库目录并验证 Key, so that 安装后马上能用

## Implementation Decisions

- **形态**：TypeScript 写的 Node 命令行工具，包名与命令名都是 `genlab`（`npx genlab` 按包名解析，二者一致才能直接调用）。工程沿用 npm-starter 模版：tsdown 打包成单个 `dist/cli.mjs`（运行依赖不打包），bumpp 发版，推送 `v*` tag 后由 GitHub Actions 经 Trusted Publishing 发布到 npm。保留 ESLint 与 Prettier，TypeScript 暂用 6（typescript-eslint 尚不支持 TS 7）。给 agent 的使用说明是仓库内的 skill（`skills/genlab`），不随 npm 包发布，用 `npx skills add WBBB0730/genlab -g -s genlab` 安装。MCP 入口以后需要时在同一套核心上再包一层。
- **复用 GenHub**：kie 的 `createTask` / `recordInfo` 封装、任务记录解析（kie 五态归约为生成中 / 就绪 / 失败三态）、版本规则。登录、项目权限、Supabase、webhook、Vercel 一概不要。
- **模型**（见 ADR-0005）：不写死，`-m` 填 kie 的模型标识。
  - 模型目录取自 `GET /api/v1/models`，素材类型由目录的任务类型推出（Text/Image to Image、Image Editing → 图片；… to Video、Video Editing、Lip Sync、Speech to Video → 视频；Text to Speech、Text to Music、Audio to Audio → 音频）；对话模型不支持，任务类型互相矛盾或未知的模型报错。
  - 参数定义取自 `GET /api/v1/models/{模型}/schema` 的 OpenAPI 文档，只支持走 `/api/v1/jobs/createTask` 的模型；文档未同步（为 null）时报错。`$ref` 用 json-schema-ref-parser 展开。
  - 目录与 schema 缓存在 `$XDG_CACHE_HOME/genlab`（默认 `~/.cache/genlab`），一天有效，`models --refresh` 强制刷新；缓存里找不到模型时自动刷新一次目录。同一进程内目录类请求保持 1.1 秒间隔（kie 限 1 次/秒），被限流时等一个间隔重试一次。
  - `models` 列出目录（可按类型、关键词筛选）；`models <模型>` 输出价格说明与参数表（参数名、类型、可选值、默认值、范围、是否必填、说明；input 为 oneOf / anyOf 时列出各分支）。
  - 在已有素材上生成时，模型的素材类型必须与素材一致。
- **参数**：`-p key=value` 为字符串，`-p key:=<JSON>` 为 JSON 值，同一个键重复即数组。按模型 schema 用 Ajv（JSON Schema 2020-12）校验，按 schema 把字符串转成数字、布尔，单值转数组；不校验 uri 等格式；错误信息用 ajv-i18n 中文化。不注入 schema 默认值，记录的就是实际发出的参数。
- **文件引用**：参数值以 `@` 开头表示文件——`@<路径>` 为本机文件（相对调用时所在目录），`@source` 为 AI 编辑的源版本，`@@` 开头为字面量 `@`。本机文件复制进素材的 `references/<生成编号>/`，生成记录里的 input 模板改写为 `@references/<生成编号>/<文件名>`；每次下单（含重试）时上传并替换成临时地址。
- **状态推进**：下单时不传回调地址，由工具自己向 `recordInfo` 轮询求证。每个 kie 任务先建一个版本壳；任务返回多个结果（如 Suno 一次 2 首）时，多出来的结果追加为同一次生成的新版本，排在该生成末尾；积分记在结果序号 0 的版本上。产物先下载到素材文件夹的临时文件，加锁确认版本仍在等待该任务后再就位，重复收取不会出错。产物的媒体类型与素材类型不符时标失败。
- **等待**：`create`、`generate`、`edit`、`retry` 提交后默认轮询到全部新版本终态才返回，默认最多等 90 秒（agent 执行命令一般 2 分钟超时），可用 `--timeout` 调整，用 `--no-wait` 提交后立即返回。没完成就返回当前状态（`pending: true`），用 `wait` 接着等；`wait` 不指定素材时等待当前项目里全部生成中的版本。
- **补收**：除 `models`、`project`、`wait` 外，任何命令运行前先把库里所有生成中的版本向 kie 查一遍，收下已完成的。kie 产物 14 天后失效，这期间都能补回。有记录、没有任务编号的版本（提交到一半中断）超过 10 分钟标失败，可重试。同一素材的写入互斥。
- **文件交付**：kie 访问不到本机文件，下单前通过 kie 的文件上传接口换成临时地址（24 小时有效、地址不带查询参数）。每次下单（含重试）都重新上传，不保存地址。
- **配置**：`$XDG_CONFIG_HOME/genlab/.env`（默认 `~/.config/genlab/.env`）存 `KIE_API_KEY` 与库的根目录 `GENLAB_LIBRARY`（绝对路径，可用 `~` 开头），已存在的环境变量优先。不放在工具目录：经 npx 运行时包在临时缓存里。未配置直接报错，不回落到任何默认位置。`genlab init` 写入该文件：终端里交互询问 API Key（掩码输入，回车沿用已有）与库目录（默认 `~/GenLab`），也可用 `--key`、`--library` 直接给出；先用余额接口验证 Key，再建好库目录、以 600 权限写入配置，输出配置路径、库目录与余额。非终端且缺 Key 时报错。仓库另提供 `.env.example`。
- **项目映射**（见 ADR-0004）：映射表 `projects.json` 放在库根目录。有远程仓库的代码项目按远程地址识别（https、scp、ssh 写法视为同一仓库），首次使用自动以远程仓库名登记，仓库名已被其他代码项目占用时报错要求指定；没有远程仓库的按主仓库所在位置识别（worktree 归到它的主仓库，不是 git 仓库的目录按目录位置），首次使用必须用 `project <名字>` 登记。查表时先按远程地址找，找不到再按位置找尚未记录远程地址的条目，找到就补上远程地址、名字不变。修改映射只改对应关系，不移动已有的素材文件夹。
- **目录结构**（见 ADR-0002）：`<库>/<项目>/<文件夹…>/<素材名>/`，素材文件夹里放记录文件 `asset.json`、各版本产物 `v<版本号>.<扩展名>`、`references/<生成编号>/` 下的参考输入副本（保留原文件名，同名加序号）。含记录文件的文件夹才是素材，素材里不能再建素材。素材名就是文件夹名，不另存。查询和补收直接扫描库目录，不建总索引。
- **文件夹**：放在哪个文件夹由 agent 指定，可以按用途分也可以按类型分，工具不按类型自动分目录。`create`、`import` 时自动建好路径上缺的文件夹。使用说明要求 agent 先用 `list` 看已有的文件夹，尽量沿用。改名、移动、删除素材或文件夹在 Finder 里做，工具不提供对应命令。
- **记录内容**：
  - 素材：编号、类型、当前版本、创建时间。
  - 每次生成：kie 模型标识、input 模板（文件为副本路径或 `@source`）、参考输入（副本位置、原文件名、类型；来自库内版本产物时另记出处素材与版本号）、源版本、创建时间。
  - 每个版本：版本号、来源（生成 / 导入）、所属生成、在生成里的序号、在 kie 任务结果中的序号、状态、失败原因、kie 任务编号、发给 kie 的原始请求、kie 返回的原始任务记录、积分、产物文件、MIME、尺寸、时长、文件大小、源版本、导入的原文件名、创建与更新时间。
- **版本规则**（见 ADR-0001）：版本号在素材内连续递增，删过的号不复用；失败的版本原地重试：发一个新任务，取它的第 1 个结果，多出来的结果同样追加为新版本。新素材的当前版本取版本号最靠前的版本（它失败时顺延）；在已有素材上生成时当前版本不动；只能把就绪版本设为当前版本。删除只限来源链叶子，素材至少保留一个版本；删除当前版本时指针回到其源版本，没有则回到最新的就绪版本。一次生成的版本全删完时，连同它的参考输入副本一起删除。
- **新建与追加分开**：`create`、`import` 遇到同名素材或同名文件夹报错；`generate`、`edit` 等指向的素材不存在时报错。`create` 校验不通过时不留下任何文件。
- **重新生成**：`generate --from <版本>` 沿用该版本所属生成的模型与 input（含参考输入与 `@source`），`-p` 给出的键覆盖沿用值；换了模型时 input 不沿用。沿用的参考输入复制进新的生成。
- **AI 编辑**：`edit` 的参数里必须用 `@source` 引用源版本；未指定模型时沿用源版本的模型，导入的版本没有模型，必须指定。`@source` 不能用在 `create` 与不带 `--from` 的 `generate` 里。
- **命令**：

  | 命令                                | 作用                                               |
  | ----------------------------------- | -------------------------------------------------- |
  | `init`                              | 写入配置（API Key 与库目录）                       |
  | `models [模型] [--kind] [--search]` | 列出 kie 模型；指定模型时输出价格与参数表          |
  | `project [名字]`                    | 查看当前代码项目对应的项目；带名字时登记或修改映射 |
  | `create <素材>`                     | 新建素材并发起第一次生成                           |
  | `generate <素材> [--from <版本>]`   | 在已有素材里发起生成；`--from` 即重新生成          |
  | `edit <素材> <版本>`                | 对某个就绪版本做 AI 编辑                           |
  | `retry <素材> <版本>`               | 原地重试失败的版本                                 |
  | `wait [素材]`                       | 继续等待未完成的版本                               |
  | `import <素材> <文件>`              | 把外部文件导入为新素材的第一个版本                 |
  | `use <素材> <版本>`                 | 设为当前版本                                       |
  | `delete <素材> <版本>`              | 删除来源链叶子版本                                 |
  | `show <素材>`                       | 查看素材的全部版本、生成输入与文件路径             |
  | `list [文件夹] [--kind]`            | 列出当前项目的素材                                 |

  生成类命令的选项：`-m/--model`、`-p/--param key=value | key:=JSON`（可重复）、`-n/--count`（并列任务数，1–10）、`--no-wait`、`--timeout <秒>`。

- **寻址**：素材用「文件夹/素材名」指定，相对当前项目；版本写 `3` 或 `v3`。参数里引用的文件位于库内某个版本产物时自动识别并记录出处。
- **输出**：见 DESIGN.md。结果是 JSON（终端里缩进，被程序读取时单行），空字段省略，路径一律绝对路径；警告与错误以 JSON 写到 stderr，出错退出码为 1。

## Testing Decisions

- 只测外部行为，用 vitest 写单测（node 环境），沿用 GenHub 纯函数单测的形态；从 GenHub 搬来的任务记录解析单测一并搬入。
- 覆盖：
  - 模型目录与参数：任务类型 → 素材类型、`-p` 解析（字符串、JSON、重复键成数组）、文件引用的收集与替换（`@source`、`@@`）、schema 取 input 并展开 `$ref`、校验时的类型转换与中文错误、参数表整理（含 oneOf 分支）。测试数据写成本地缓存，单测不访问网络。
  - 项目映射：远程地址归一、自动登记、同一远程的多个副本、未登记报错、中途建远程、仓库名被占用。
  - 版本规则：当前版本的失败顺延、删除后的指针回退、叶子判定、版本号分配。
  - 生成全流程：在临时目录里跑真实文件系统，kie 网络层用替身——并列任务与收取、文件上传与模板改写、失败顺延、一个任务多个结果追加版本、产物类型不符、下单失败、同名 / 嵌套 / 校验失败 / 未知模型 / 误用 `@source` 报错且不留文件、AI 编辑、重新生成、重试、删除与参考输入清理、导入与库内出处。
- 单测不真实调用 kie。真实冒烟须经用户同意并控制花费（2026-11-03 用户授权 ¥10 以内，两轮合计约 171 积分 ≈ ¥6.2）。改为动态模型后已验证：模型目录与参数表、参数校验报错、GPT Image 2.5 Sunburst 文生图与 AI 编辑（`@source`）、Suno V6 Mini 音乐与音效（一个任务 2 个结果追加为 2 个版本）、Wan 3.0 首帧图生视频（`@文件` 与库内出处）、重新生成、`genlab init`（写入、沿用、Key 无效、缺 Key）。此前写死模型阶段另验证过 Wan 3.0 文生视频、Wan 2.7 视频编辑、MiniMax H3、Suno AI 编辑与项目映射。

## Out of Scope

- 网页界面、登录、成员、角色与可见性。
- GenHub 内容重组后的概念：按提示词自动起名、批次、「我的」、跨项目复制。
- 导出命令与导出位置记录。
- 对话模型、手工编辑。
- MCP 入口。
- 导入线上 GenHub 的数据。
- 回收站、用量统计、按提示词搜索。
- 按素材类型自动分目录。
- 改名、移动、删除素材或文件夹的命令。
- kie 回调与 webhook。

## Further Notes

- 选择自己写而不用 kie-cli-mcp：它最核心的缺口正好是不把成品存到本地，而它的大部分功能（几十个模型、生成前出计划并确认）用不上。
- ElevenLabs 语音模型在 2026-11-03 冒烟时均在 kie 侧排队后上游超时失败（退款，记 0 积分），kie 成功率接口显示同期成功率为 0；工具侧行为正确，产物链路待 kie 恢复后再验证。
- kie 账号的余额可能同时被其他用途消耗，核算花费以各版本记录的积分为准。
- 包名原为 `genhub`（沿用网页版的名字），首次发布时被 npm 以「与 `github` 过于相似」拒绝，改名为 `genlab`；npm 的相似名检查只在发布时执行，事先查不到。
- kie 文档中的参数定义偶有自相矛盾（如默认值不在可选值里），以 schema 校验加 kie 实际返回为准；参数不合法时 kie 在下单阶段拒绝，不扣积分。
