# 代码项目 → 项目：代码项目里的 .genlab 点目录，未关联时必须明确选择

取代 ADR-0004。代码项目对应库里的哪个项目，记在代码项目里的 `.genlab/` 点目录中（`project.json` 写项目名），点目录自带只含 `*` 的 `.gitignore`，忽略自身，不改动代码项目的任何忽略设置。规则只有一条：

- 关联写在执行 `genlab project link <项目>` 时所在的目录；查找时从当前目录逐级向上取最近的关联。不判断是否为 git 仓库，也不读取远程地址。
- 当前目录没有关联时，素材相关的命令一律报错，列出已有项目和关联命令，要求明确选择：关联到某个项目，或关联到内置项目 `default`。
- 项目必须先用 `genlab project create` 建好，关联到不存在的项目报错；`default` 一直存在，首次放入素材时自动建好文件夹。
- 任何素材命令可用 `--project` 临时指定项目，只对这一条命令生效，不改动关联。

## Considered Options

- **库根目录下的映射表，按远程地址 / 主仓库位置识别（ADR-0004）**：为推算「当前项目」需要识别规则、登记、自动登记、补写远程地址、重名报错，临时目录、跨项目生成、并发等新场景各要再加规则。被否。
- **素材路径写全「项目/文件夹/素材」，不设当前项目**：没有隐含状态，但每条命令都要写项目名，「这个代码项目用哪个项目」只能由 agent 每次判断。被否。
- **未关联时自动放进 `default`，关联后再挪过去**：挪动要改写其他素材里指向它的出处，并处理同名冲突；不挪则素材悄悄放错地方。被否。
- **按是否为 git 仓库决定未关联时报错还是用 `default`**：不是所有项目都用 git，规则因此分叉。被否。
- **关联写进代码项目的 `.gitignore` 或 `.git/info/exclude`**：前者给每个仓库多一处要提交的改动，后者依赖 git。点目录自带忽略文件与 pytest 缓存目录、Python venv 的做法一致，两者都不需要。被否。
- **默认项目用单独的参数表示**：同一件事出现两种写法。改为保留名 `default`，与 AWS CLI 的 profile、kubectl 的 namespace 一致。

## Consequences

- 与 Vercel（`.vercel/`）、Netlify（`.netlify/`）、Supabase 的关联方式一致：关联只对本机有意义，不随仓库提交。
- 新 clone，以及建在仓库目录之外的 worktree，第一次使用时按报错提示关联一次；建在仓库目录之内的 worktree 向上即可找到关联。
- 原映射表不迁移：库里已有的项目文件夹保留，每个代码项目第一次使用时关联一次。
