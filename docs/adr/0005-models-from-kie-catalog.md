# 模型不写死：清单与参数实时取自 kie 的模型目录与 schema

可用模型来自 kie 的模型目录接口（`GET /api/v1/models`），参数定义来自每个模型的 OpenAPI 文档（`GET /api/v1/models/{模型}/schema`）。`-m` 直接填 kie 的模型标识，`-p` 的键就是 schema 里 input 的字段名，按 schema 校验并转换类型；文件以 `@<路径>` 写在对应字段里，AI 编辑的源版本写 `@source`，由工具上传后换成地址。素材类型由目录的任务类型推出；一个任务返回几个结果就建几个版本。目录与 schema 本地缓存一天。

写死模型表时，工具替 agent 决定了参考文件填哪个字段、文生与图生如何切换、一次出几个结果，但只能覆盖少数模型，kie 上新增、改名、下线的模型要靠改代码跟进。kie 提供目录与 schema 后，模型和参数可以按官方定义直接使用，覆盖全部图片、视频、音频模型且不会过时；schema 不描述的语义（字段的作用、模型的配对）交给 agent 读参数表决定，这也是 kie 官方 skill 的做法。

## Considered Options

- **写死精选模型（原实现）**：调用写法统一（`--prompt`、`--ref`、自动切换文生 / 图生），但只有十几个模型，维护跟不上 kie 的变化。被否。
- **精选模型 + 直通任意模型**：两套写法、两套校验并存，精选表仍要维护。被否。
- **全部动态，再给常用模型配别名与默认参数**：省一点 agent 的事，但别名本身又是一份要维护的清单。被否。
- **按字段名自动猜参考文件的去向（如名字带 url 的字段）**：不同模型的字段名与含义各不相同，猜错要到下单甚至出结果才发现。被否。

## Consequences

- agent 用一个模型前要先看 `genlab models <模型>` 的参数表，并显式指定文件填进哪个字段。
- 代码不评价模型好坏，列表按目录顺序反转为从新到旧。使用说明写明图片、视频、音乐与音效的默认模型，不随 kie 目录自动更新；其他任务由 agent 按列表顺序与版本号挑选。
- 文生与图生常是两个模型标识，由 agent 按是否带输入图选择；重新生成沿用原模型与 input。
- 版本数事先未知：每个被 kie 接受的任务先建一个版本，多出来的结果在收取时追加为新版本。
- 只支持走 `/api/v1/jobs/createTask` 的模型；对话模型、schema 尚未同步的模型、任务类型矛盾的模型直接报错。
- 参数校验依赖 kie 文档的准确性；文档有误时以 kie 下单阶段的拒绝信息为准（不扣积分）。
- 目录类接口限 1 次/秒，靠本地缓存与请求间隔避免限流。
