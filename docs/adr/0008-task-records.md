# 任务记在所属生成里：积分与耗时属于任务，重试追加新任务

素材记录里每个生成带一个任务列表，一个任务记 kie 任务编号、发给 kie 的原始请求、kie 返回的原始任务记录、积分、耗时（kie 的 `costTime`，秒）与创建时间。版本只用 `taskId` 指向产出它的任务。重试失败的版本时，新任务追加进所属生成，版本改指新任务，重试前的任务原样保留。命令输出里，积分与耗时在 `tasks` 里按任务列出，不挂在版本上。

积分与耗时是 kie 按任务给出的：Suno 一个任务出两首，扣一次积分、只有一个耗时。原先这些数据挂在版本上，积分只能挑结果序号 0 的版本记，序号 1 的版本看起来没花钱，序号 0 的版本被删后这笔花费就查不到了；重试会覆盖版本上的任务数据，kie 已扣费但产物下载被拒的那次花费随之丢失。记在任务上，每笔积分只出现一次，直接相加就是真实花费，删版本、重试都不丢。

## Considered Options

- **仍记在版本上，积分只记结果序号 0**：不改记录格式，但上面的问题都在。被否。
- **每个版本都记所属任务的全部积分与耗时**：每个版本都看得到，但直接相加会重复计算，汇总时要先按任务去重。被否。
- **积分按结果数均摊到版本**：相加仍是总花费，但记的是算出来的数而不是 kie 给的，除不尽时出现循环小数。被否。
- **任务放在素材记录顶层，与生成、版本并列**：删光一次生成时要另外清理它的任务；放在生成里随生成一起删除，与参考输入副本一致。被否。
- **重试时用新任务替换旧任务**：记录更短，但重试前花掉的积分查不到。被否。

## Consequences

- 素材记录升到第 3 版。读第 2 版记录时按任务编号把版本上的任务数据归并成所属生成的任务，积分与耗时取自 kie 原始记录；重试前已被覆盖的任务无从恢复，下单时间取版本的创建时间。0.1.4 及更早的版本读不了第 3 版记录。
- 一个生成可能有没有版本指向的任务（重试前的任务）。不指定版本的输出（如 `show`）列出素材的全部任务；生成类命令与 `wait` 只列所列版本所属的任务。
- 耗时取 kie 的口径（从接单到出结果），不含上传参考输入与下载产物；收取是否及时不影响它。
