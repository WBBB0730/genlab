# 库以素材为核心：沿用 GenHub 内容重组之前的模型

库的组织沿用 GenHub（团队的网页版生成工具）在「以内容为中心」重组之前的模型：**项目** → 可嵌套的**文件夹** → **素材** → **版本**。素材由调用者起名，同一文件夹内不重名；版本按版本号排列，来源链完整记录；素材持有当前版本指针；失败的版本原地重试；只能删除来源链叶子。GenHub 重组后新增的按提示词自动起名、批次、「我的」、跨项目复制都不采用。

GenHub 重组时去掉起名，是为了让人在网页上少一步操作；agent 起名几乎没有成本，这个理由在这里不成立。反过来，有意义的名字（如「角色/主角立绘」）是 agent 和用户共同指代素材的稳定称呼，接着改、取用都靠它；一个素材也自然对应代码项目里的一个具体文件，当前版本就是正在用的那一版。「同一文件夹内不重名、文件夹可嵌套」恰好也是文件系统自己的规则（见 ADR-0002）。批次在 GenHub 里只是展示分组，版本属于哪次生成本来就记在来源链里，不需要单独的概念。

## Considered Options

- **GenHub 重组后的模型（自动起名 + 批次）**：适合人在网页上随手出图；但自动起的名字长且会重复，agent 只能靠编号指代素材。被否。
- **每次生成一个文件夹、按日期归档（最初草案）**：结构最简单，但没有素材这一层，同一个东西的多轮修改散落在不同日期下，版本链无从谈起。被否。

## Consequences

- 新建素材必须给名字，同一文件夹内重名直接报错，不自动改名。
- 重新生成、AI 编辑都发生在同一素材内，新版本接着往后编号。
- GenHub 的版本规则（当前版本的选择与回退、叶子删除、原地重试）原样适用。
