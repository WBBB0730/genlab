# 库就是文件夹：素材 = 文件夹 + 记录文件，不用数据库、不建总索引

库直接用文件系统表达：项目、文件夹、素材都是真实的文件夹，层级即 `<库>/<项目>/<文件夹…>/<素材名>/`。每个素材文件夹里放一个记录文件（素材、生成、版本的全部信息）、各版本产物和参考输入副本。素材名就是文件夹名，不另存。查询历史、收取未完成的生成都直接扫描库目录，不维护数据库或总索引。

这样用户在文件管理器里看到的就是库本身：给素材或文件夹改名、移动、删除，直接操作即生效，工具不必提供对应命令；也不存在「索引和磁盘对不上」这类问题。单人本机的素材规模下，每次扫描的开销可以忽略。

## Considered Options

- **SQLite 存记录 + 文件夹存产物（延续 GenHub 用数据库的做法）**：查询方便，但用户在文件管理器里改名、移动、删除后数据库就与磁盘失步，要么禁止手动整理，要么做同步修复。被否。
- **文件夹 + 一份总索引文件**：同样会与手动整理失步。被否。

## Consequences

- 记录文件是素材的唯一真相，格式变化必须能读懂已有素材的记录。
- 含记录文件的文件夹才是素材；素材里不能再放素材或文件夹。
- 同一素材的写入必须互斥，否则多个 agent 同时操作会互相覆盖。
- 在文件管理器里移动素材后，别的素材里记下的「参考输入出自哪个素材」会过时，这类出处只作参考。
