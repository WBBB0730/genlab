# 代码项目 → 项目：映射表 + 按远程地址 / 主仓库位置识别

代码项目对应库里的哪个项目，由库根目录下的一张映射表决定，每条记录项目名、远程地址和主仓库位置。识别规则：

- 有远程仓库的代码项目按**远程地址**识别，首次使用时自动以远程仓库名登记。
- 没有远程仓库的按**主仓库所在位置**识别（worktree 归到它的主仓库，不是 git 仓库的目录按目录位置），首次使用必须由 agent 或用户指定名字。
- 查表时先按远程地址找；找不到，再按位置找尚未记录远程地址的条目，找到就补上远程地址、名字不变——覆盖「一开始没有远程仓库、中途才建」的情况。
- 之后一律查表。表可以手动改：改名、或把多个代码项目指向同一个项目；改映射只改对应关系，不移动已有的素材文件夹。

## Considered Options

- **用目录名**：本地目录名常与远程仓库名不一致（如目录 game-dev 的远程是 pixel-quest），不同项目也可能撞名（一个仓库的远程名恰好等于另一个项目的目录名）。被否。
- **每次让 AI 自己取名**：AI 每次重新判断，可能取出 pixel-quest、PixelQuest、pixel-game 等不同名字，无法保证一致。被否。
- **只用远程仓库名，不建映射表**：零配置，但没有远程仓库的项目每次都得显式指定名字，又回到一致性问题；也没法把多个仓库归到同一项目。被否。
- **在代码项目里放一个写明项目名的配置文件**：任何项目都适用，但每个项目要多提交一个文件；在 worktree 里定的名字合并回主分支前，其他副本看不到，可能被再定一次。被否。
- **只按目录位置识别**：worktree、目录改名、重新 clone 都会被当成新项目。被否。

## Consequences

- 同一远程仓库的多个副本（如 game-dev 与 game-dev-experiment）自动归到同一项目。
- 只剩两种情况认不出来：没有远程仓库的代码项目换了位置；远程地址变了。此时会被当成新项目，需要手动改表。
- 映射表随库一起存放，库搬家时映射跟着走。
