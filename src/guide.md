# genlab 使用说明

用 kie.ai 的模型生成图片、视频、音频，产物与完整生成记录保存在本机的库里。

下文的 `genlab` 均可写作 `npx -y genlab@latest`（推荐，每次都用最新版本）。

## 准备

- 报错「缺少配置」时，请用户在终端运行 `genlab init`，填写 kie.ai API Key 与库目录。
- 库目录在代码项目之外。在沙箱里运行时，需要允许读写库目录与 `~/.cache/genlab`（模型目录缓存），并允许访问网络。

## 概念

- **项目**：库里最外层的分组。当前目录用 `genlab project link` 关联到一个项目后，素材命令都作用于它；`--project` 临时指定其他项目，不改关联。
- **默认项目**：内置的 `default`，一直存在，放不属于任何代码项目的素材。
- **素材**：项目里的一个创作单元，用「文件夹/素材名」指定，文件夹可省略（如 `characters/hero`、`logo`）。类型为 image / video / audio，由第一次生成的模型或导入的文件决定，之后的生成须用同类型的模型。
- **版本**：素材的一个产物。版本号在素材内递增，删过的号不复用；状态为 generating / ready / failed。
- **当前版本**：素材选定的那一版。新素材默认取版本号最小、没有失败的版本（还在生成中也等它）；用 `genlab use` 改选。
- **AI 编辑**：以某个就绪版本为源版本、按要求修改，新版本仍属于同一素材。

## 流程

1. `genlab project` 查看当前目录关联的项目。没有关联时先关联：
   - 属于某个代码项目：关联到对应的项目，库里还没有就先 `genlab project create`。
   - 不属于任何代码项目（家目录、临时目录、下载目录等）：关联到 `default`。
   - 判断不了：问用户。不要为了省事把属于某个项目的素材放进 `default`。
   - 关联的项目不存在（可能已改名或删除）：问用户要关联到哪个，不要新建同名项目。
2. `genlab list` 查看已有素材与文件夹，新素材沿用已有的文件夹分法。
3. `genlab models --kind <类型> [--search <关键词>]` 找模型，`genlab models <模型>` 查看价格与参数表。参数名以参数表为准，不凭记忆填。文生与图生常是两个模型（`…-text-to-image` / `…-image-to-image`），按是否带输入图选择。
4. 用户没指定模型时，为新素材的第一次生成挑 2–3 个候选（模型、价格、特点）请用户选；同一素材之后的生成默认沿用该模型（需要带输入图时换成同系列的图生模型），不再询问。
5. `create` 新建素材，`generate` 在已有素材里生成，`edit` 做 AI 编辑，`retry` 重试失败的版本。命令默认最多等 90 秒；输出 `"pending": true` 时用 `genlab wait` 继续等。同时为多个素材发起生成时加 `--no-wait`，再用 `genlab wait` 一起等。
6. 生成完向用户汇报使用的模型（版本的 `model`）、消耗的积分（各版本 `credits` 之和）与折合美元（kie 基础价 1 积分 = $0.005）。
7. 每个版本的 `file` 是产物的绝对路径；一个任务可能产出多个版本（如一次出两首的音乐模型）。用户选定后用 `genlab use` 设为当前版本；需要放进代码项目时自行复制该文件。

## 模型参数（-p）

- `key=value`：字符串；数字、布尔、数组按参数表自动转换。
- `key:=<JSON>`：JSON 值，如 `-p duration:=5`。
- 同键重复即数组，如 `-p input_urls=@a.png -p input_urls=@b.png`。
- `@<路径>`：本机文件（相对当前目录），自动上传；引用库里的产物时直接用它的 `file` 路径。
- `@source`：AI 编辑的源版本文件，只能用在 `edit`。
- `@@`：字面量 `@`。

## 规则

- 生成消耗 kie 积分：先看价格，任务数、分辨率、时长按需设置。
- 不手动修改库里的 `asset.json`；改名、移动、删除整个素材由用户在文件管理器里操作。
- 项目、文件夹、素材的名字用英文。
- 结果为 JSON；错误写 stderr 的 `{"error": ...}`，警告为 `{"warning": ...}`。
